> 本文为V0.1历史记录。当前工程已切换为[完整音效V0.3](音效V0.3接入与验收.md)，新版替换落地声、增加UI/投放/胜负/BGM等，不再使用下述旧落地变体或8级临时音。

按 `小游戏音效/catbox-audio-v1/使用说明.txt` 接入10条原始WAV；不导入MP3或整段试听。原文件均为48kHz、16bit、单声道，未归一化、未改写采样。说明、清单与SHA-256保存在 `docs/audio-source/`。

| 游戏事件 | 文件 |

本包没有投放、按钮、失败、背景音乐，不使用其他声音代替。

## 规则与配置

- 碰撞音对应物理接触触发的软弹起点。同一物理步先收集碰撞，再完成合成，最后只给存活实体播放落地声；同级待合成接触不播放落地声。
- 低于72像素/秒的轻触、65毫秒内重复接触、同一猫160毫秒内重复接触不播放；静置抖动不响。音量按接触速度在0.35–1间调整。
- 总音量0.85，最多3个可停止的AudioSource；合成优先于落地，拥挤时丢弃低优先级反馈，不积压后续播放。
- 晃箱遇到合成降低5dB，持续0.3秒后恢复；最后0.06秒淡出。无效晃箱不播放。
- 暂停、切后台、静音立即停止并清除待播放音效；继续或取消静音不重播旧短音效。重开、回首页及场景销毁也完整清理。
- 首页声音开关和设置页开关同步控制播放器，并沿用本机声音偏好保存。

参数集中在 `AudioConfig.ts`。`GameAudio.ts` 负责资源与三路音频池；`GameController.ts` 负责按玩法事务触发，`CatEntity.impact()` 返回是否真正开始软弹。计分与胜负不依赖音频加载、播放或完成回调。单条资源加载失败时跳过该音效并记录警告。

## 运行与验证

Creator 3.8.8 打开 `assets/scenes/CatBox.scene`，浏览器预览。点击首页开始后进行投放；确认首页声音图标没有斜线。Web构建可通过 `npm run serve` 后访问 http://localhost:8080/ ，旧页面需要刷新。

类型检查、9项规则检查通过；Creator Web Mobile构建成功。16项音效检查通过：10条WAV实际解码、真实重力落地、轻重分配、同级合成单次反馈、变体不重复、静置静音、3路限制、8级临时音、5dB降低、0.8秒停止、静音清除异步待播、暂停/后台/重开及首页设置。通过真实触摸解锁浏览器音频，在默认自动播放限制下，确认WebAudio实际启动了具有非零采样的音频缓冲。

上述为播放路径验证，不是人工听感验收。微信小游戏构建、微信真机、手机外放与耳机听感、目标平台的音量控制和WAV播放延迟仍待验证。优先根据真机体验调整总音量、接触阈值、碰撞间隔及晃箱音量。

回归结果：38项玩法、13项成功结算、11项生命周期检查均通过，覆盖30次重开、12次通关重开、音频节点销毁与资源加载中断。没有修改物理参数、等级概率、得分或胜负规则。
