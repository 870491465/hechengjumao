# 成功结算页接入与验收

依据用户提供的 `结算页资源/win-assets` 中README、manifest、texts及《合成成功原型图.png》接入。使用PNG，不加载WebP；图片保持比例，可见区域按alpha>24裁取。素材说明归档在 `art-source/win/`。

| 来源资源 | 使用方式 |
| --- | --- |
| game-background | 成功页全屏等比覆盖背景，使用本包提供的原图 |
| win-celebration | 独立光芒、星星和彩纸，置于主插画后 |
| win-hero | 橘猫和纸箱整体插画，只做整体轻微回弹，不拆分，不参与碰撞 |
| win-title | 含星星的成功标题，保留图片文字 |
| win-score-panel | 双列底板，叠加真实本局得分与最高分 |
| win-record-badge | 仅严格超过此前最高分时显示，保留素材中的文字 |
| win-button-replay | 与首页开始按钮逐字节一致，复用首页贴图，叠加“再玩一次” |
| win-button-home | 与首页帮助按钮逐字节一致，复用首页贴图，叠加“返回首页” |

## 行为与文件

- `WinView.ts`：成功页贴图布局、分数展示、轻微入场回弹、按钮反馈、长屏铺满及返回前台后的继续遮罩。不提交分数，不生成猫实体。
- `ArtAssets.ts`：6张新增PNG的尺寸与裁取配置；两张按钮复用已加载资源。
- `GameController.ts`：沿用首次合成8级即时锁定通关，原有1.5秒庆祝阶段后展示成功页；仍以单次结算保护防止重复。刷新最高分前先记录是否为新纪录，之后提交真实最高分。
- `tools/win-check.cjs`：通过真实7+7物理合成触发成功，检查记录条件、单次展示、按钮不穿透、后台暂停及反复结算清理。

得分与最高分不依赖动画回调。低于或等于历史最高分均不显示新纪录徽章。再玩一次清理旧局并进入新局，返回首页清理旧局并恢复首页。切后台时视觉动画冻结；返回前台后须点击继续。失败结算现已接入独立失败素材，详见《失败结算页接入与验收》。

成功页采用固定宽度适配，背景等比铺满长屏，布局按屏高调整。离开成功页时恢复玩法原有适配。所供素材属于原型图的重绘版本，插画细节存在源素材本身的差异。

## 运行与验证

Creator 3.8.8 打开 `assets/scenes/CatBox.scene`，浏览器预览，从首页开始，首次合成8级后进入成功页。已更新Web Mobile构建；`npm run serve` 后访问 http://localhost:8080/ ，刷新旧页面。

类型检查与9项规则检查通过，Web Mobile构建成功。13项成功页运行检查通过，包括实际7+7合成、真实分数、严格新纪录、重复结算保护、恢复前台点击继续、再玩/首页按钮和12次通关重开清理。截图已检查720×1280与390×844。验证截图中的分数来自测试局数据，不是界面写死值。

38项玩法回归和11项生命周期检查通过，包括暂停、晃箱、胜负优先级、30次重开、5次场景重载及加载过程中销毁。压力段为60个物体、5秒模拟时间。

截图：`win-screenshots/win.png`、`win-screenshots/no-record.png`、`win-screenshots/mobile.png`。

真机、微信小游戏和低端设备性能尚未验证；没有增加音效、广告或分享功能。
