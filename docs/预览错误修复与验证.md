# 编辑器预览错误修复

日期：2026-10-23。依据为本机 `temp/logs/project.log` 中的实际堆栈。

## targetOff 空引用

`DropInput.dispose → Node.targetOff` 在 Canvas 的 `GameController.onDestroy` 中被调用，但 Creator 3.8.8 的父节点销毁顺序是先销毁子节点及其事件处理器，再销毁父节点组件。原代码持有一个已失效的输入节点引用，因而访问到内部已经清空的事件处理器。

已修正：

- `DropInput.ts` 捕获输入节点，在节点销毁事件中释放输入；释放具有幂等性，使用 `isValid(node, true)` 判断能否解绑，清除触点并断开节点引用。
- `CatEntity.ts` 同样允许节点/碰撞体先被场景销毁，避免控制器随后清理时再次访问失效碰撞体。
- `GameView.ts` 只清理自身创建的视觉根节点，并跳过已经销毁的节点。
- `GameController.ts` 增加销毁状态、加载中节点清理和严格生命周期检查；资源异步完成后不会重建已经关闭的游戏。重复销毁也不会重复改变物理系统状态。

## 编辑器帧缓冲错误

`FRAMEBUFFER_INCOMPLETE_MISSING_ATTACHMENT` 的堆栈为 `EditorPreview._startEditor → PreviewManager.init → ScenePreview/MiniPreview → PreviewBuffer.createWindow → RenderWindow.initialize`。报错发生在 Creator 内嵌预览缓冲初始化；当前堆栈没有进入玩法或猫图加载函数。具体显卡/窗口初始化原因尚未在内嵌模式确认。

本地 `profiles/v2/packages/preview.json` 的预览平台已由 `gameView` 改回 Creator 自带默认的 `browser`，开始场景仍为 CatBox。这个文件是本机编辑器偏好，不是发布包设置。浏览器运行保持美术、mipmap、物理和交互规则原样。

操作步骤：停止当前内嵌预览，清空旧日志，在 Creator 顶部预览下拉中选择“浏览器”再启动。若当前编辑器还保留旧的下拉选项，手动选择一次或重新打开工程。也可以运行 `npm run serve` 后访问 `http://localhost:8080` 的最新构建产物。

**范围说明**：空引用已经由项目代码修复；帧缓冲问题采用浏览器预览兼容路径规避，尚未宣称 Creator 内嵌渲染问题已被修复。没有修改或屏蔽安装引擎的帧缓冲检查。
