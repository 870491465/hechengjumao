## 身体对齐

有效区域只是裁去留白，不能直接当成碰撞圆。对 alpha>180 的身体左右和下部轮廓（源图 Y≥400，排除耳部）做圆拟合，并人工查看拟合轮廓：

| 等级 | 原图身体圆心 X,Y | 原图身体半径 | 实际游戏半径 |
| --- | --- | --- | --- |
| 1 | 626.38,646.04 | 443.90 | 24 |
| 2 | 625.97,651.23 | 453.87 | 33 |
| 3 | 627.07,646.83 | 444.86 | 45 |

美术等比缩放系数为 `游戏半径 / 原图身体半径`，并按身体圆心与取图区域中心的偏差平移。身体原点对应刚体原点；耳朵等装饰自然保留，不加碰撞体。主体侧/底部轮廓的拟合 95% 误差约为原图 8.5–11.3 像素，约为半径的 2–2.5%；不是像素级完美圆。

支持非 2 次幂 mipmap 的图形后端为猫图启用线性 mipmap 缩小过滤（本机实际生成 11 级），避免 1254 像素原图缩至小猫时出现细线闪点。WebGL1 保留原有线性过滤回退。未修改 PNG，也未把过滤后的像素尺寸写回碰撞参数。

美术层结构为 `Cat（刚体与圆碰撞） → CatArtwork（软弹） → CatPicture（滚动） → Sprite（裁图与身体偏移）`。围绕身体中心旋转，不围绕包含留白的整张画布中心旋转。待投放、当前和下一只预览调用相同的映射及身体缩放函数。

半径表、密度/质量、重力、速度限制、投放冷却、合成保护、配对、危险判定和计分规则均未修改。

## 场景与界面

节点顺序明确为 `RoomBackground → BoxBackLayer → Cats/DropGuide → BoxFrontLayer → CollisionOutlines → HUD`。调试轮廓层默认不可见。

- 背景按比例 cover 720×1280 设计画布，不拉伸猫和纸箱。保持既有 SHOW_ALL 手机适配，长屏上下留空。
- 后板源包内边界为 left=.092、right=.908、top=.03、floor=.938。使用九宫格只调整中间纸面长度，边框保持统一缩放；内侧线对应 X=±300，内底为 Y=-430，箱口为 Y=230。未把源包旧的 W=320/H=432 写回物理场景。
- 后板装饰侧板不参与碰撞；整图略超出设计画布左右边缘，外侧少量装饰可被画布裁去，内侧边界完整保留。
- 前沿等比绘制，最高覆盖到内底上方 8 个设计单位，低于最小猫直径 48 的 1/5；不会整块盖住底部猫咪。
- 后板与前沿一起做轻微水平视觉晃动，物理墙原位不动。
- 晃箱按钮底图按原比例放入点击区域，分数、剩余次数、冷却和弹窗文字仍为 Label；没有把动态文案烘焙为图片。

## 软弹

保留真实接触速度/法线驱动的衰减压扁和回弹，正式猫的最大压缩输入限制为 .16，实际峰值更低，避免过强穿插。合成额外做 .22 秒、最高 6% 的轻微视觉放大回弹。只影响美术子节点，不改实体 scale、碰撞半径或质量。贴底保持接触侧不悬空，贴墙收住身体形变；耳部装饰仍可能有轻微自然突出。

## 调试开关

默认关闭。Creator 中选择 Canvas，在 GameController 上勾选 `Show Collision Outlines` 后预览；运行时也可取消该属性。Debug 浏览器构建可打开 `http://localhost:8080/?colliders=1`，不带参数恢复默认关闭。它显示真实圆心、半径和箱内边界，不会根据贴图或动画变形。

## 主要修改

- `ArtAssets.ts`：素材预加载、裁图、身体校准、等比 Sprite、纸箱九宫格及前沿定位。
- `GameView.ts`：渲染分层、统一猫图工厂、按钮图、真实文字和可选碰撞轮廓。
- `CatEntity.ts`：猫图跟随刚体滚动；保留独立软弹并增加合成轻微放大。
- `GameController.ts`：启动预加载、加载期间后台暂停处理、默认关闭的调试属性。
- `assets/resources/art/`：7 张原始 PNG 与 Creator metadata。
- `tools/art-check.cjs`：美术映射、身体对齐、图层、纸箱边界、回退、实际触摸和合成换图检查。

## 运行与验证

Creator 3.8.8 打开项目，等待导入结束，打开 `assets/scenes/CatBox.scene` 后浏览器预览。资源由代码预加载，无需手工拖拽绑定。如编辑器保留了旧的灰盒预览缓存，重新打开工程后再预览。

已有最新 Web Mobile 构建时运行 `npm run serve`，访问 `http://localhost:8080`；同 Wi-Fi 手机访问电脑局域网 IP 的 8080 端口。规则与业务类型检查为 `npm run check`，自动运行检查为 `npm run test:runtime`，美术专项为 `node tools/art-check.cjs`（Playwright 配置方式沿用原验证文档）。

## 本轮最终验证结果

- 严格业务 TypeScript 检查通过，9 组无引擎规则测试通过。
- 最新 Web Mobile / Debug 构建完成，日志为 `build Task (web-mobile) Finished in (18 s)`；实际复制回 `build/web-mobile` 并独立加载该产物，未以编辑器旧预览或源码拦截替代。
- **41 项美术专项检查通过**：7 张资源成功加载，1–3 级正确映射/身体圆心和半径/等比/滚动原点/质量不变；4–8 级数字回退；渲染图层；后板内侧与底板几何对齐；前沿最多覆盖 8；背景/前沿等比；预览同步；调试默认关闭并可切换；合成换图与计分；左右中真实触摸。
- **38 项玩法回归通过**：包含固定投放 Y、冷却与多指、碰撞/合成去重、晃箱、计分、同一步通关优先失败、暂停/后台处理、连续 30 次重开、60 刚体 5 秒模拟及两种手机比例坐标检查。未重新宣称完成 5 分钟真机性能测试。
- 页面没有资源加载/游戏脚本 error。7 张项目 PNG 与外部源文件 SHA-256 全部一致，见 `art-source/source-hashes.json`。
- 已人工复查 [游戏画面](art-source/screenshots/art-play.png)、[碰撞轮廓](art-source/screenshots/art-colliders.png)、[390×844 画面](art-source/screenshots/art-mobile.png)。截图为构造混合棋盘并经过真实引擎落稳的检查场景，包含缺失素材等级的数字回退。

本机可用提交内存较低，标准构建器按 16 核创建压缩 worker 时发生 `spawn UNKNOWN`/内存不足。最终验证采用临时 Creator **3.8.8 工具副本**，仅将该压缩插件的 worker 数限制为 1；已安装的 Creator 和正在使用的编辑器均未修改。通过目录联接确认引擎是同一批实际源文件，并验证了 741 个依赖时间戳后复用原有引擎缓存，未修改引擎物理代码或功能开关。构建器仍有 GPU 缓存占用、中文可执行文件名回退、默认压缩选项和管线 chunk 提示；判断依据包含最终产物的独立运行检查。项目正常打开/运行不依赖这个临时工具副本。
