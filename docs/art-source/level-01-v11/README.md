**交付状态：可接入验证的分层素材候选包。文件级与拼合检查已完成，尚未在现有 Cocos 工程中完成验收，不标记为最终生产通过。**

## 交付目录

- `source/`：真正可编辑的 OpenRaster 分层源文件 `.ora`、嵌入图层的 `.svg`、512原图参考。
- `sprites/`：12张独立、同坐标对齐的正式透明PNG。
- `pose_references/`：四张512×512透明姿势参考，不是四帧直接循环的动画。
- `preview/`：完整透明拼合图、拼合展示、四姿势对照、支点说明、呼吸眨眼GIF。
- `alignment.json`：身体中心、支点、层序、姿势参数和Cocos坐标换算。
- `manifest.json`：正式PNG清单及可见区域。
- `QA.json`：检查结果及尚未验证的项目。

## 对齐与坐标

左右一律以**画面观看者**为准。像素坐标原点在左上角，X向右、Y向下。

- 所有正式贴图及姿势参考：512×512。
- 身体动画中心：**(256, 272)**。
- 参考碰撞圆：中心(256,272)，半径176像素，仅用于美术校准，**不是对既有游戏物理半径的新配置**。
- 保留原图完整Alpha轮廓。原角色轮廓并非数学正圆，耳朵和部分毛边允许偏出参考圆。
- 在Cocos中保持已经验收的圆碰撞体参数不变；只缩放视觉节点，不缩放RigidBody/Collider节点。
- 建议禁止自动裁切SpriteFrame透明边距，或正确恢复originalSize/offset。验证阶段按完整512画布显示。

### Cocos中使用完整画布部件的方法

全画布Sprite统一使用(0.5,0.5)锚点，不要各自按可见轮廓居中。

若所有贴图直接放在以身体中心为原点的visualRoot下，统一Sprite位置为 **(0,16)**：身体中心比画布中心低16像素，需要将画布上移16像素。

若为爪子建立支点节点：
1. 支点节点放到上表的Cocos位置。
2. 将该部件Sprite作为支点子节点，位置为 `(256-pivotX, pivotY-256)`。
3. 仅旋转/平移支点节点。完整换算也记录在alignment.json。

表中是512画布的美术像素；若游戏采用其他显示比例，位置、视觉尺寸和支点偏移需要乘以同一个显示比例。

## 默认叠放顺序

从后到前：body → 左后脚 → 右后脚 → 左前爪 → 右前爪 → mouth_normal → 左眼 → 右眼。

同侧眼睛只启用一种状态。默认完整拼合使用原图闭眼；GIF演示使用小幅睁眼待机并短暂切换半闭/闭眼。

## 源文件格式与限制

当前流程没有生成原生PSD的能力，**没有伪造PSD**。

- `source/cat_level_01.ora` 是实际OpenRaster分层文件，12个独立命名图层，含隐藏的备选眼睛状态；可用支持OpenRaster的软件（如Krita）打开编辑。已检查栈重组与拼合PNG一致（8位通道最大差1）。
- `source/cat_level_01.svg` 是嵌入12张RGBA图像的独立分组SVG，保留层名与可见性，可选中每组编辑。图层内是栅格图，不冒充可编辑毛发矢量路径。
- 身体隐藏区域由图像工具补画，再限定补画区域合入原图；原图轮廓、耳朵、主体外侧、鼻子和腮红尽量保留原始像素。毛发填补处不是原图中被遮住区域的真实还原。
- 爪子使用原图像素及向身体内部延展的毛发根部。前爪小幅活动的参考范围为约±6px、±6°，不适合大幅伸展或完整骨骼肢体动作。
- 半闭眼是同一新绘小眼睛的几何压缩版，闭眼为原图线条；共用定位中心，可见包围框中心差不超过0.5px（栅格抗锯齿造成）。
