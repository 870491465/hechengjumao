# 猫箱挤挤：灰盒原型交付

本轮基于现有空工程实现，使用 **Cocos Creator 3.8.8、Box2D 2D、TypeScript**。没有引入第三方游戏运行依赖，没有更换引擎版本。项目及祖先目录未发现适用的 AGENTS.md。

## 启动和试玩

1. 在 Cocos Dashboard 用 **3.8.8** 打开本项目目录，等待资源和脚本导入完成。
2. 双击 `assets/scenes/CatBox.scene`，保存并设为当前场景。
3. 点击编辑器上方浏览器预览按钮。场景中的 Canvas 挂载 GameController，运行时自动生成纸箱、刚体和界面，无需手工绑定资源。编辑状态下不绘制整套游戏界面是正常的。
4. 建议预览设备选手机竖屏，例如 720×1280 或 390×844。游戏使用 720×1280 设计尺寸、SHOW_ALL 等比适配，较长屏幕上下留空，箱内比例及按钮相对位置不变。
5. 构建发布选择 **Web Mobile**，开始场景选择 CatBox，输出到 `build/web-mobile`。本机已生成一份可试玩的 Debug 构建。

直接试玩构建产物：在项目根目录执行 `npm run serve`，电脑访问 `http://localhost:8080`。手机与电脑连接同一 Wi-Fi，访问 `http://电脑局域网IP:8080`。不要直接双击构建目录的 HTML。服务默认监听局域网；结束试玩可 Ctrl+C 关闭服务。

在电脑上查询当前局域网 IP，用手机打开 `http://电脑局域网IP:8080/`。防火墙是否允许手机访问由本机网络设置决定。

可选命令行构建：在未用编辑器占用该工程时运行 Creator，参数为 `--project "项目绝对路径" --build "configPath=项目绝对路径/tools/build-web.json"`。配置文件已指定 Web Mobile 和开始场景。编辑器开启时优先使用编辑器构建，避免并行访问资源库。本次构建验证在独立临时工程副本完成，再将构建产物复制回本项目；无需用户使用该副本。

## 已完成的玩法

- 开口纸箱、固定物理墙与底板、常显虚线危险线；危险时红线闪烁与倒计时。
- 点击投放、拖动预览后松手投放、箱外起手不接受、出生按半径和安全间距夹边、出生占用拒绝投放且不推进队列。
- 当前与下一只预览，前四只 1/1/2/1，随后 60%/30%/10%，0.6 秒投放冷却，单有效触点，按钮与弹窗拦截输入。
- 8 个等级，圆形碰撞体、同密度质量、低恢复系数与阻尼、速度限制和刚体休眠。数字球体支持滚动，数字保持正向。
- 真实接触驱动合成；每物理步收集接触，按距离和 ID 排序选取互不重复的配对；保护期间保留持续接触，0.10 秒后可继续连锁；锁定源实体后同步移出物理参与，动画不提交分数。
- 合成位置取中点并夹边，有限向上修正重叠，最大搜索位移为产物半径；拥挤时由求解器处理，限制速度，不额外施加合成爆炸冲量。
- 每局两次晃箱，0.8 秒固定交替加速度，动作结束后 3 秒冷却；速度贡献有界，主动唤醒；只移动箱体绘制，物理墙保持原位。晃动禁止投放但继续合成和危险计时。
- 按产物基础分和 1 秒窗口计分，倍率 1/1.2/1.4/1.6/1.8；接受新投放或晃箱才断开旧连锁，失败操作不消耗队列/次数或重置连锁。
- 新投放 1.2 秒保护且需参与箱内猫或底板接触才开始危险判定；合成继承较早保护截止时刻；持续越线 3 秒失败，全清线 0.2 秒后清零。
- 首个 8 级产物立即通关，先提交合成与分数再检查失败；约 1.5 秒通关提示后结算。胜负均幂等，结算提供重开。
- 暂停、继续、暂停中重开；物理和局内所有计时使用同一固定游戏时钟。切后台暂停，返回后手动继续，不重抽队列；通关展示阶段切后台也等待玩家继续。
- 重开清理实体、碰撞索引、接触缓存、分数、危险/冷却/连锁、输入触点、晃箱状态和提示，恢复空箱与两次机会。

本轮按要求不制作首页、专用引导局、图鉴、跨启动存档、正式美术、音效、商业化或网络服务。操作说明常驻界面。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `assets/scenes/CatBox.scene` | 可直接运行的入口，Canvas、Camera、GameController |
| `assets/scripts/GameConfig.ts` | 等级、尺寸、概率、分值、冷却、危险、物理和晃箱参数 |
| `assets/scripts/Rules.ts` | 纯规则：队列、可复现随机、稳定配对、连锁、危险计时、结算状态 |
| `assets/scripts/CatEntity.ts` | 实体、圆形碰撞体、刚体、接触监听、物理限速、独立美术子节点 |
| `assets/scripts/MergeSystem.ts` | 持续接触缓存、配对候选、产物位置修正 |
| `assets/scripts/DropInput.ts` | 有效区域、首触点、拖动预览、取消与投放 |
| `assets/scripts/ShakeController.ts` | 次数、冷却、固定加速度曲线、有界速度贡献 |
| `assets/scripts/GameView.ts` | 灰盒绘制、预览、按钮、提示与结算弹窗；替换猫资源从 `ball()` 入手 |
| `assets/scripts/GameController.ts` | 固定步主循环、事务提交、出生、胜负优先级、暂停及生命周期 |
| `tests/rules.test.cjs`、`tools/check.cjs` | TypeScript 与无引擎规则测试 |
| `tools/runtime-check.cjs` | 真实引擎浏览器自动验证，含触摸输入与加速物理稳定性场景 |
| `tools/build-web.json`、`tools/serve.cjs` | 构建选项和无依赖的本地/局域网试玩服务 |

没有全局 DOM 输入监听、场景重开回调链或每猫计时器。`Session` 及实体字段是后续保存局面的小型接入点，本轮不做落盘。实体的 `art` 子节点是美术替换入口，动画缩放只作用于这个子节点。

## 规则解释与工程取舍

- 按早期试玩反馈将箱高由 `1.35W` 调为 `1.10W`（810→660）。后续加入4级随机投放时，为避免等待猫遮挡头部，将固定出生点与箱口间距从 `0.24W`（144）调整为 `0.20W`（120）。当前底部Y=-430、箱口Y=230、出生Y=350；箱体与猫咪半径不变。上述用户需求覆盖PRD首轮测试初值，详见《4级随机投放调整》。
- 待投放球常驻箱口上方，使用与物理出生点相同的父节点局部坐标，但没有刚体或碰撞体。一次接受投放后队列推进，新的当前球立即进入等待预览；冷却期间降低透明度。点击/拖动只选 X，不修改出生 Y。
- 触摸通过 `getUILocation()` 取得 UI 世界位置，再转换到实际刚体父节点 `Cats` 的局部坐标；等待预览反向通过同一父节点转换到界面坐标。输入 Y 仅用于判断是否在有效点击区域，不能传入投放函数。实体从固定 Y、零初速开始，由重力推进，没有飞向点击点/箱底的移动动画。

- PRD 半径和分数全部保留。复核所有半径后，无需修正面积关系：各次合成确实释放总面积。开发过程中曾口头误判，未更改任何尺寸参数。
- 固定物理步为 1/60 秒。Cocos 3.8.8 的 `PhysicsSystem2D.gravity` 接口接受像素/秒²，`RigidBody2D.linearVelocity` 则采用米/秒，按 32 像素/米换算，保证重力为 -1.8W/秒²、最大速度为 1.5W/秒。
- 使用引擎公开的手动步进和场景同步接口，逐步完成碰撞、合成、危险判断，使同一步通关优先于失败。长帧每帧最多追赶 6 步，所有计时同步随游戏模拟推进，不追算后台时间。
- 晃箱曲线每 0.1 秒交替一次水平加速度，幅值 2.5W/秒²；每个刚体累计的晃箱速度贡献限制为 ±0.25W/秒。冷却从动作结束开始计算。
- 物理侧墙延伸到画面之外，防止高处合成绕过墙端；每个物理步还检查左右与底部越界，保留微小接触容差，不增加箱口顶盖。可见墙仍只画到箱口。
- 普通碰撞与合成均有按受力方向压扁、横向鼓起、衰减回弹的果冻表现；只缩放美术子节点，半径不变。贴墙和晃箱时会收住形变轮廓，避免视觉穿墙。
- 全清线宽限的 0.2 秒内保留已有危险累计；没有危险猫的瞬间不额外累计。重新出现危险时接续，持续全清线才清零。
- 8 级产物显示 1.5 秒胜利提示，期间冻结棋盘；暂停与结算均冻结刚体，不依赖 tween/schedule/动画完成回调。
- `tsconfig.json` 启用严格业务类型检查，跳过 Creator 自带 `.d.ts` 内部错误；没有用忽略业务错误掩盖编译问题。
- Debug 构建含 `window.__catGame` 自动验证入口；Release 构建的 `DEBUG` 为 false，不暴露此入口。

## 验证方式与边界

在本项目运行 `npm run check`。该命令从 Creator 自动生成的 `temp/tsconfig.cocos.json` 定位已安装引擎的 TypeScript，无需安装游戏依赖。未首次打开工程时可设置 `COCOS_CREATOR_ROOT` 指向 Creator 安装根目录。

浏览器自动验证需要 Playwright 和 Chromium。可设置 `PLAYWRIGHT_MODULE` 为已安装的 Playwright 模块目录、`CHROMIUM_PATH` 为浏览器可执行文件，`CATBOX_URL` 为 Debug 构建地址，再执行 `npm run test:runtime`。默认测试 `http://localhost:7456`；测试构建产物应明确设为 `http://localhost:8080`。60 刚体默认跑 30 秒模拟时间，可用 `CATBOX_STRESS_SECONDS=300` 延长。测试脚本会重建测试局，仅用于验证页面。

测试 Creator 预览可设置 `CATBOX_PREVIEW=1`，脚本会请求 CatBox 场景；`CATBOX_SOURCE_SCENE=1` 是资源库尚未刷新时的开发用选项，最终构建验证不启用这两个选项。

已完成严格 TypeScript 检查、9 组规则测试、Creator 3.8.8 Web Mobile 构建及真实 Box2D 的浏览器运行检查。详细最终结果见 `docs/灰盒原型-验证记录.md`。

**尚未验证**：真实 iOS/Android 设备手感、微信小游戏构建及真机生命周期、中低端基准机实际连续 5 分钟平均帧率/内存。加速模拟不等于真实设备性能验收。浏览器模拟触摸通过也不代替手机触摸验收。

## 手机验收顺序

1. 空箱连续点击同一列，观察前四只为 1/1/2/1；前两只合成后首次得 10 分；投放和普通碰撞不加分。
2. 快点、双指、左右边缘点按；0.6 秒内只接受一只，圆球不会从侧墙外生成。拖动后松开确认位置预览。
3. 点暂停、继续、晃箱、弹窗按钮；不应额外投球。暂停后等 5 秒，位置、危险剩余时间、冷却不变化。
4. 观察晃箱消耗一次，持续约 0.8 秒，期间不能投猫；结束再等 3 秒才能用第二次；不可用点击不扣次数。
5. 往箱内堆高，检查正常下落不会直接触发失败；已有堆叠持续越线显示 3 秒倒计时，全清线后 0.2 秒复位。晃箱不会停住倒计时。
6. 手机切后台再返回；必须点继续才下落，当前/下一只不重抽。
7. 失败后反复“再装一箱”，应恢复空箱、0 分、1/1 预览和两次晃箱；暂停中也可重开。
8. 正常玩法合成 8 级检查通关和最终分数；极端同一步胜负优先级已由自动测试构造验证。

## 建议优先调的手感参数

先试 `gravityRatio=-1.8`、`linearDamping=0.4`、`friction=0.35`、`dropCooldown=0.6`。晃箱效果优先调 `shakeAccelerationRatio=2.5` 与 `shakeHalfPeriod=0.1`，维持速度贡献上限；不要用移动碰撞墙增强效果。难度再考虑出猫概率、箱高与尺寸。一次调整一组参数并重跑规则与物理测试。
